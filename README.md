# Zara Stock Alert — установка

Бот проверяет нужные товары/размеры на zara.com и присылает уведомление в
Telegram, как только размер появляется в наличии.

Работает на GitHub Actions — бесплатно, ничего не нужно держать включённым
у себя на компьютере.

**Расписание:** Пн–Пт, 15:00–19:00 по Вашингтону, проверка каждые 5 минут.
**Уведомления:** один раз на каждое появление размера (без повторов).

> Когда всё настроите, для повседневной работы вам понадобится только файл
> **КАК-ОБНОВЛЯТЬ-ТОВАРЫ.md** — там про добавление и удаление товаров.

---

## Шаг 1. Создать Telegram-бота (3 минуты)

1. В Telegram найдите **@BotFather** (с синей галочкой) и нажмите Start.
2. Отправьте команду `/newbot`.
3. Он спросит имя бота — напишите любое, например `Zara Alert`.
4. Потом спросит username — он должен быть уникальным и заканчиваться на
   `bot`, например `elena_zara_alert_bot`. Если занято, попробуйте другой.
5. В ответ придёт **токен** вида
   `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx` — скопируйте и сохраните
   его где-нибудь. Это ключ, никому его не показывайте.
6. **Важно:** нажмите на ссылку с вашим ботом в сообщении BotFather, откройте
   чат с ним и отправьте боту любое сообщение (например `привет`). Без этого
   бот не сможет вам писать.
7. Откройте в браузере адрес, подставив свой токен вместо `<ВАШ_ТОКЕН>`:

   ```
   https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates
   ```

   В ответе найдите `"chat":{"id":123456789,` — число после `"id":` это ваш
   **chat_id**. Тоже сохраните.

   *Если ответ пустой (`"result":[]`) — вернитесь к пункту 6 и напишите боту
   сообщение, затем обновите страницу.*

---

## Шаг 2. Создать репозиторий на GitHub

1. Зайдите на github.com под своим аккаунтом.
2. Справа вверху **+** → **New repository**.
3. Заполните:
   - **Repository name:** `zara-stock-alert`
   - **Public** — оставьте выбранным. Для публичных репозиториев минуты
     Actions бесплатны без лимита. Ваши токены при этом остаются скрытыми
     (см. шаг 4). Приватный тоже сработает, но там лимит 2000 минут в месяц —
     нашему боту этого впритык хватит, лучше выбрать Public.
   - Галочки «Add a README» и прочие — **не ставьте**.
4. **Create repository**.

---

## Шаг 3. Загрузить файлы

На странице пустого репозитория будет ссылка **uploading an existing file** —
нажмите её. (Или адрес `https://github.com/ВАШ_ЛОГИН/zara-stock-alert/upload/main`)

1. Распакуйте архив `zara-stock-alert.zip` у себя на компьютере.
2. Перетащите в окно браузера **содержимое** папки `zara-stock-alert` —
   то есть сами файлы, а не папку целиком:

   ```
   check_stock.py
   products.json
   state.json
   requirements.txt
   README.md
   КАК-ОБНОВЛЯТЬ-ТОВАРЫ.md
   .github/          ← папку перетащите тоже, структура сохранится
   ```

3. Внизу нажмите **Commit changes**.

> **Если папка `.github` не видна в Finder:** это скрытая папка. В Finder
> нажмите `Cmd + Shift + .` (точка) — скрытые файлы станут видны. Повторное
> нажатие скроет их обратно.
>
> **Если перетащить `.github` не получилось**, создайте файл вручную:
> на главной странице репозитория **Add file → Create new file**, в поле
> имени введите `.github/workflows/check_stock.yml` (слэши создадут папки
> автоматически), вставьте содержимое файла из архива → **Commit changes**.

Проверьте, что в репозитории видно все 5 файлов и папку `.github`.

---

## Шаг 4. Добавить секреты (токен и chat_id)

В репозитории: **Settings** (вкладка сверху) → в левом меню
**Secrets and variables** → **Actions** → зелёная кнопка
**New repository secret**.

Добавьте два секрета, по одному:

| Name | Secret |
|------|--------|
| `TELEGRAM_BOT_TOKEN` | токен из шага 1, пункт 5 |
| `TELEGRAM_CHAT_ID` | число из шага 1, пункт 7 |

Имена нужно ввести **точно так**, заглавными буквами с подчёркиваниями.
Секреты не видны публично, даже если репозиторий Public — и их нельзя
посмотреть после сохранения, только заменить.

---

## Шаг 5. Список товаров

`products.json` **уже заполнен** вашими 38 товарами — на этом шаге ничего
делать не нужно. Дальше добавлять и убирать товары вы будете сами: как
именно — в файле **КАК-ОБНОВЛЯТЬ-ТОВАРЫ.md**.

---

## Шаг 6. Включить и проверить

1. Откройте вкладку **Actions**. Если появится плашка *"Workflows aren't being
   run on this forked repository"* или предложение включить workflows —
   нажмите зелёную кнопку согласия.
2. Слева выберите **Zara Stock Check** → справа **Run workflow** → зелёная
   кнопка **Run workflow**.
3. Через минуту обновите страницу, откройте появившийся запуск → шаг
   **Run stock check**. В логе будет видно, что нашёл скрипт.

   Если вы запускаете вне окна Пн–Пт 15:00–19:00, в логе будет строка
   «вне окна проверки» — это нормально, значит всё работает правильно.

4. Дальше бот работает сам.

**Как проверить, что Telegram настроен верно:** временно поставьте в
`products.json` любой товар с размером, который точно есть в наличии.
При ближайшем запуске (внутри рабочего окна) должно прийти сообщение.

## Важно знать

- **Задержки расписания.** GitHub Actions может запускать задачи с опозданием
  на 1–5 минут в часы пиковой нагрузки. Для 5-минутного интервала не критично,
  но мгновенной реакции ждать не стоит.
- **Спячка через 60 дней.** Если в репозитории 60 дней нет активности, GitHub
  отключает расписание. Достаточно зайти в Actions и нажать «Run workflow»
  (или отредактировать `products.json`), чтобы включить обратно.
- **Защита от ботов.** Скрипт делает обычные, неагрессивные запросы к
  страницам товаров, с паузой 2–5 секунд между товарами — без обхода капчи и
  защиты. Если Zara начнёт отвечать ошибками, правильное решение — увеличить
  интервал проверки (в `.github/workflows/check_stock.yml` заменить `*/5` на
  `*/15`), а не пытаться обойти защиту.
- **Сайт может поменяться.** Если Zara изменит структуру страниц, в логах
  Actions появится предупреждение «не нашли данные о наличии» — тогда код
  нужно будет подправить.
- **Нагрузка при 38 товарах.** Один прогон занимает ~1,5–2 минуты и делает 38
  запросов к сайту. При проверке каждые 5 минут это около 1800 запросов за
  рабочее окно. Это заметная нагрузка, и Zara теоретически может начать
  отвечать ошибками. **Если в логах пойдут строки «не удалось загрузить
  страницу»** — увеличьте интервал: в `.github/workflows/check_stock.yml`
  замените `*/5` на `*/10` или `*/15`.
- **Цвета.** Ссылки в вашем списке содержат хвост `?v1=...` — это код цвета.
  Скрипт проверяет именно выбранный цвет. Если в логе появится «не удалось
  сопоставить v1 с конкретным цветом», он проверит все цвета товара — тогда
  уведомление может прийти по неподходящему цвету. Посмотрите на это в первом
  же запуске: если такие строки есть у всех товаров, скажите мне — поправлю.

## Что где лежит

| Файл | Зачем | Трогать? |
|------|-------|----------|
| `products.json` | Ваш список товаров и размеров | **да, только его** |
| `check_stock.py` | Логика проверки и отправки уведомлений | нет |
| `state.json` | Память бота: о чём уже уведомлял | нет (обновляется сам) |
| `requirements.txt` | Список Python-библиотек | нет |
| `.github/workflows/check_stock.yml` | Расписание запусков | только если меняете интервал |
