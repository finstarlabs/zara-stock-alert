# Как обновлять список товаров

Всё, что нужно менять — это **один файл: `products.json`**. Ничего другого
трогать не нужно. Изменения вступают в силу автоматически при следующей
проверке (в течение 5 минут, если вы внутри окна Пн–Пт 15:00–19:00).

---

## Где находится этот файл

`https://github.com/ВАШ_ЛОГИН/zara-stock-alert/blob/main/products.json`

Проще всего добавить эту ссылку в закладки браузера.

---

## Как редактировать (прямо в браузере, ничего устанавливать не надо)

1. Откройте ссылку выше.
2. Нажмите на **карандаш** (✏️ Edit this file) в правом верхнем углу файла.
3. Внесите изменения (см. рецепты ниже).
4. Прокрутите вниз → зелёная кнопка **Commit changes** → ещё раз
   **Commit changes** в окошке.
5. Готово. Никаких дополнительных действий не требуется.

> Если GitHub подсветит строку красным при редактировании — значит, где-то
> ошибка в запятых или кавычках. Не сохраняйте, пока красное не исчезнет.
> Если всё же сохраните с ошибкой — бот пришлёт вам в Telegram сообщение
> «⚠️ Ошибка в файле products.json» с номером строки.

## Как устроена запись о товаре

```json
  {
    "name": "Полосатое платье миди",
    "url": "https://www.zara.com/us/en/striped-midi-halter-dress-p07484158.html",
    "sizes": ["S", "M"],
    "active": true
  }
```

| Поле | Что это | Обязательно |
|------|---------|-------------|
| `name` | Как товар будет называться в уведомлении. Любой текст, можно по-русски. | да |
| `url` | Ссылка на страницу товара на zara.com (не на Favorites). | да |
| `sizes` | Список нужных размеров в кавычках через запятую. Регистр не важен: `"m"` = `"M"`. | да |
| `active` | `true` — следим за товаром, `false` — временно не следим. Если поле не указать, считается `true`. | нет |

### Про размеры обуви с половинками

Скрипт понимает все эти написания как один и тот же размер:

```
"7.5"   "7½"   "7 1/2"   "7,5"
```

Пишите как удобнее — проще всего `"7.5"`, чтобы не искать символ ½ на
клавиатуре.

### Про цвета

Хвост ссылки `?v1=495698341` — это код конкретного цвета. Скрипт старается
проверять именно тот цвет, что вы выбрали, и подставляет его название в
уведомление.

Из этого следует важное: **если вам нужен один и тот же товар в двух цветах —
добавьте две записи** с разными `v1` (как сделано в вашем списке для анорака
и марлевой рубашки). Скопируйте адрес из браузера отдельно для каждого цвета.

Если в логе появится строка *«не удалось сопоставить v1=… с конкретным
цветом»* — ничего страшного: скрипт проверит все цвета товара сразу. Тогда
уведомление может прийти по цвету, который вам не нужен.

**Правила формата (это JSON, он придирчив):**

- Весь файл — от `[` до `]`.
- Каждый товар — в фигурных скобках `{ }`.
- Между товарами — **запятая**. После **последнего** товара запятой быть
  **не должно**.
- Все тексты — в двойных кавычках `"..."`. Не одинарных, не «ёлочках».
- `true` и `false` пишутся без кавычек и с маленькой буквы.

## Рецепт 1. Добавить новый товар

Найдите последний товар в списке, поставьте после его закрывающей скобки `}`
запятую и вставьте новый блок:

```json
[
  {
    "name": "Первый товар",
    "url": "https://www.zara.com/us/en/....html",
    "sizes": ["M"]
  },
  {
    "name": "Новый товар",
    "url": "https://www.zara.com/us/en/....html",
    "sizes": ["S", "M"]
  }
]
```

Где взять ссылку: откройте товар на zara.com, **выберите нужный цвет** →
скопируйте адрес из адресной строки браузера целиком, вместе с хвостом
`?v1=...`. Именно этот хвост говорит скрипту, какой цвет вас интересует.

---

## Рецепт 2. Перестать получать уведомления о товаре

Два варианта — выбирайте любой.

**Вариант А (мягкий): выключить, но оставить в списке.** Удобно, если позже
захотите вернуть. Добавьте товару строку `"active": false`:

```json
  {
    "name": "Больше не актуально",
    "url": "https://www.zara.com/us/en/....html",
    "sizes": ["M"],
    "active": false
  }
```

Чтобы снова включить — поменяйте `false` на `true`.

**Вариант Б (жёсткий): удалить полностью.** Удалите блок товара целиком — от
`{` до `}` — и лишнюю запятую рядом с ним. Проверьте, что после последнего
оставшегося товара запятой нет.

---

## Рецепт 3. Поменять размеры у существующего товара

Отредактируйте список в `sizes`:

```json
"sizes": ["S"]              → следим только за S
"sizes": ["S", "M", "L"]    → следим сразу за тремя размерами
"sizes": ["XS"]             → следим только за XS
```

---

## Рецепт 4. Очистить список полностью

Если хотите начать с нуля, содержимое файла должно быть ровно таким:

```json
[]
```

---

## Как понять, что всё работает

1. В репозитории откройте вкладку **Actions** → «Zara Stock Check».
2. Нажмите **Run workflow** (можно в любое время суток — вне рабочего окна
   скрипт просто напишет в логе, что сейчас не время проверки).
3. Откройте последний запуск → шаг **Run stock check** → там будет видно,
   какие товары проверены и что найдено. Например:

```
[ok] Полосатое платье миди: новых размеров нет (сейчас доступно: —)
[notify] Джинсы прямые: M
[info] Пальто: размера XL нет в списке размеров этого товара. Доступные варианты: S, M, L
```

Строка `[info] ... нет в списке размеров этого товара` — подсказка, что вы
опечатались в размере: сверьтесь с тем, как размер называется на сайте.

## Про файл `state.json`

Это служебная память бота: он помнит, о каких размерах уже сообщил, чтобы не
слать одно и то же повторно. **Редактировать его не нужно** — он обновляется
сам.

Единственный случай, когда его стоит тронуть: если вы хотите получить
уведомление о товаре заново, хотя он уже в наличии. Тогда откройте
`state.json`, замените всё содержимое на `{}` и сохраните.

## Частые вопросы

**Я добавила товар — когда начнётся проверка?**
При ближайшем запуске: каждые 5 минут в окне Пн–Пт 15:00–19:00 по Вашингтону.
Вне этого окна бот ничего не делает.

**Придёт ли уведомление дважды?**
Нет. Уведомление приходит один раз — в момент, когда размер появился. Если
размер пропал и появился снова, придёт новое уведомление.

**Бот молчит уже неделю — он сломался?**
Скорее всего нет, просто размер не появлялся. Проверить можно через Actions →
Run workflow (см. выше). Отдельно: GitHub отключает расписание, если в
репозитории 60 дней не было активности — тогда во вкладке Actions будет
жёлтая плашка с кнопкой, чтобы включить обратно. Любое редактирование
`products.json` тоже считается активностью и сбрасывает этот счётчик.
